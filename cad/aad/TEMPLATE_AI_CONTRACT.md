# AAD canonical template — AI project authoring contract (v1)

**Canonical engine:** `/cad/aad/multistorey/` using `public/assets/js/aad-building-core.mjs`, `aad-unified-workspace.mjs` and `aad-building-ifc4.mjs`. The stable `/cad/aad/` URL opens that engine; `/cad/aad/legacy/` is a preserved, superseded text-command demonstration. All projects (including Narayani) refer to the canonical engine; they **must not fork it**.

## AI-first interaction

The intended client is an AI assistant that converts a natural-language request and source evidence into **validated structured AAD model actions or versioned project files**. A user should not need to type internal CAD commands into the page. The static GitHub Pages site has no built-in LLM, agent credentials, autonomous Drive reader or cloud database. **Do not claim it does.** ChatGPT or another user's authorized AI can author and commit the structured inputs through its own connected GitHub workflow, or operate a browser automation agent that invokes the validated browser API.

For existing, locally loaded projects, the shared studio exposes `window.AADStudio`:

- `getCapabilities()`: machine-readable version and supported methods
- `getSnapshot()`: exact current building manifest, floor graphs, derived building and version
- `selectElementById("PRJ-000007:gf:EXT-01")`: select, reveal and highlight in plan, 3D and schedule (same ID)
- `change({level:"gf",kind:"wall",id:"EXT-01",patch:{thickness:0.23}})`: validate and update a wall
- `change({level:"gf",kind:"opening",id:"WIN01",patch:{width:1.45}})`: validate hosted window dimensions
- `change({level:"gf",kind:"node",id:"N19",patch:{x:10.03}})`: move a connected wall node, with geometry/area QA
- `setLevel("gf"|"ff"|"sf"|"all")`
- `getDraft()`: versioned `jp-cad://aad-working-draft/1` JSON, for export/reimport

### Connected wall and hosted object drafting (M15)

The common engine, not a project-specific fork, implements these structured, atomic topology actions:

```js
AADStudio.topology({level:"gf",action:"addWall",
  args:{start:{x:2.5,z:1},end:{x:8.4,z:7},thickness:0.15}});
AADStudio.topology({level:"gf",action:"splitWall",args:{wallId:"W01",offset:2.5}});
AADStudio.topology({level:"gf",action:"joinWalls",args:{firstId:"W01",secondId:"AIS-0001"}});
AADStudio.topology({level:"gf",action:"removeWall",args:{wallId:"AIW-0001"}});
AADStudio.topology({level:"gf",action:"addOpening",
  args:{wallId:"AIW-0001",kind:"door",offset:1.2,width:.9,sill:0,height:2.1}});
AADStudio.topology({level:"gf",action:"removeOpening",args:{id:"AID-0001"}});
AADStudio.getRooms("gf");
```

Every topology action clones the working draft, snaps endpoints to existing junctions or hosting segments, splits crossed segments and remaps hosted-opening offsets where feasible, checks storey outline/IFC consistency, and only then updates 2D, 3D, component schedule, draft and IFC4 writer. Generated IDs start with `AIN-`, `AIW-`, `AIS-`, `AID-` or `AIWIN-`. Source project geometry remains versioned and unmodified.

The canonical studio additionally supports **two-click interactive wall drafting** inside an individual floor and explicit split/join/delete and door/window hosting. Closed **room-loop candidates** are computed from the connected floor graph and shown in the plan and a room table. These computed loops are **not certified `IfcSpace` geometry**, and they do not amend the source architectural area schedule. Multi-way intersections are intentionally protected against topology-destroying joins; opening overlaps and exterior removal are rejected.

The current editor is a topology-capable architectural working-draft engine, **not unlimited AI architectural synthesis or a structural-design substitute**. Construction/foundation/structural calculations require their own verified model design and QA.


**Policy:** Change commands require supported metric coordinates. Reject invalid/missing host references, zero-length walls, invalid opening envelopes, unsupported column continuity and geometrically invalid footprints. The current engine supports validated **numeric edits to existing connected graphs**, not an arbitrary-language CAD agent nor unlimited topology editing. A newly designed footprint is generated by an AI using the versioned files below, then loaded into the canonical engine.

## New project format (code reuse, not fork)

An AI submits a project-only data package under `public/data/projects/<project_slug>/`:

1. `aad-building-v1.json`: `jp-cad://aad-building/1`, projectId, storeys with elevation, transforms, model filenames and source area schedule; explicit structural/stair assumptions and provenance.
2. `<floor>.json` for each floor: existing `jp-cad://linked-one-bay-demo/0.5` AAD editable `floorGraph` (ordered exterior `perimeter`, nodes with (x,z), connected walls, hosted openings, semantic room labels).
3. An engineering evidence/provenance ledger showing measured, assumed and rejected quantities, dimensions, source file hashes and approvals.

The generic template is opened using the same-origin manifest query `/cad/aad/multistorey/?manifest=/JP_Computer-Aided-Drawings/data/projects/<project_slug>/aad-building-v1.json`. Narayani's project webpage is a thin adapter to this route. The shared model is the sole geometry/IFC source.

Validate from repository root:

```sh
node tools/site/aad-validate-project.mjs public/data/projects/<project_slug>/aad-building-v1.json
```

The CLI does not need a project-specific engine and does not alter source data. A successful geometric or IFC import **never** claims site survey, design approval, construction clearance or valid member capacities. The source-area schedule remains authoritative, and any changed area is an explicit QA deviation. Export is IFC4, with independent IfcOpenShell CI checks for deployed projects.

## Selection contract

All physical assembly elements have stable IDs `projectId:level:elementId`. Clicking a 2D authored wall/door/window, a 3D geometry mesh or a row in the schedule invokes one selected-element state: all three present an amber selection indicator, and the inspector resolves its provenance and editable parameters. For a 3D-only structural element, show its **plan location marker**, not a fictitious 2D footprint. Nonphysical control nodes receive a 3D editing marker but are not incorrectly represented as IFC products. No project-specific selection logic is permitted.

## Governance

Edit **template first**, then add/update only project data and thin project links. GitHub Actions must validate the shared engine, backwards-compatible legacy example, synchronized 2D/3D selection, IFC4 parser readback and real Pages browser interaction before publishing. Leave the previous Pages deployment and frozen structural packages recoverable.
