# Open Architecture CAD Studio M02 — linked geometry and sections

**Implementation:** candidate for `main`, synthetic demo only; no project engineering approval.

M02 keeps the `fabin-cad://canonical-boxes/0.1` model and adds optional `links`. Source coordinates in `elements` stay authored; the resolved view is derived on each edit and on all Python exports, with a single directed dependency graph.

## Link types
- `center_on_top`: XY centre and vertical support placement for a driven column on a parent footing; optional offsets.
- `span_columns_x`: beam spans from one column centre to another, updating beam length and height. M02 supports aligned, X-directed column pairs only.

**Invariants:** unique child driver, stable IDs, existing references, cycle rejection, reversed-span rejection, 200 mm maximum Y centre misalignment, finite offsets, and positive dimensions. Validation fails closed. Every user edit remains draft-only, and linked derived coordinates are locked in the inspector. Moving a source footing recomputes its column and dependent beam. Source raw model is not silently rewritten.

## Visual sections
The viewport includes a new source-driven, explicitly labelled **longitudinal (X–Z)** or **cross (Y–Z)** section. The SVG view computes intersections of axis-aligned demonstration solids with a configurable vertical plane and shows their real model-derived rectangles. This is not a detailed structural section, or a substitute for arbitrary exact OCCT sections.

## Shared five-engine source
- Browser **Three.js** geometry and read-only **web-ifc** import remain functional.
- Python **IfcOpenShell**, **OpenCascade/OCP**, and **ezdxf** now derive geometry from the same typed source dependencies before emitting IFC4, STEP or DXF.
- Frontend uses `cad/parametrics.ts`; backend uses `backend/cad_bridge/constraints.py`.

## Reproducibility
- Run `npm ci && npm run build` and `python -m unittest discover -s backend/tests -v`.
- GitHub workflow `CAD M02 Parametric Geometry QA` executes a genuine headless WebGL browser test on a locally served Vite preview and validates Python geometry/export parity.
- The acceptance edit to `FOOTING_A1.x_mm` +200 follows `COL_A1.x_mm` +200 and `BEAM_FRONT.x_mm` +200; computed beam length -200. Derived longitudinal section, undo and redo are also tested.

## Boundaries
No Narayani real dimensions. No sanctioned engineering design, code approval, physical reinforcement, real openings, multi-axis oblique beams, structural FEM or BBS. No server-hosted IFC authoring; separate Python bridge still required. All original project pages and prior CAD release history remain unaffected.
