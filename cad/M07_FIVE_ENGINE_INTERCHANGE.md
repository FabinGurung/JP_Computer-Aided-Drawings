# M07 | Five-engine source-linked geometry round-trip

## Purpose

Complete a **single verifiable interchange path** across Three.js, web-ifc, IfcOpenShell, OpenCascade/OCP and ezdxf without changing the site's chosen long-term design. This is a reusable local tool, not a replacement for the CAD Studio frontend. It is not a construction-issue or code-compliance release.

| Component | M07 execution | Verified boundary |
| --- | --- | --- |
| ezdxf | Parse the original native DXF INSERT geometry, verify each real block bbox/circular definition; export independent native plan rectangles/circles with tagged source handles | No DWG conversion; source SHA must exactly match M05 |
| IfcOpenShell | Generate IFC4 IfcColumn objects with parametric IfcRectangleProfileDef or IfcCircleProfileDef and exact extruded lengths | All IFC objects explicitly PROVISIONAL; user-attested verticals |
| OpenCascade/OCP | Exact BREP rectangular solids/cylinders; STEP export | Source geometry only; not engineering quantity approval |
| web-ifc | Re-import the generated IFC into browser WASM | Read-only IFC meshes; no semantic rewrite |
| Three.js | Display the imported IFC geometry in the existing workspace | Does not overwrite canonical editable model |

**Input:** actual source DXF (not duplicated to public GitHub), M05 `fabin-cad://semantic-column-review/0.1` JSON, M06 `fabin-cad://vertical-observations/0.1` JSON with documented heights. M05 and M06 project IDs and fingerprints must match; DXF SHA256 is recalculated from actual original bytes.

**Local command:**

```bash
python -m pip install -r backend/requirements.txt
python -m backend.cad_bridge.vertical_cli \
  --source-dxf /private/native-structural.dxf \
  --plan /private/column-plan-reviewed.json \
  --vertical /private/vertical-observations.json \
  --out-dir /private/M07-run-001
```

The output folder must be empty to prevent accidental overwrite. A typical run produces `columns.dxf`, `columns.ifc`, `columns.step` and `manifest.json` with element IDs, SHA256 checksums and `engineering_release=HOLD`.

**Shape fidelity:** Circular columns preserve diameter as native DXF CIRCLE, IFC4 IfcCircleProfileDef with IfcExtrudedAreaSolid, and analytical OpenCascade cylinder. Rectangular columns preserve exact profile XY extents. Z elevations/heights come only from M06 user-attested inputs. No silent box substitution for circles.

**Source identity:** object key `grid__from_level__to_level` and a source DXF INSERT handle; unique IFC Tags/UUIDv5 for stable identity. IFC geometric display imports read-only into Three.js using web-ifc.

### Restrictions and remaining work

The source references entered in M06 are **not independently authenticated**, even though the M07 original DXF bytes are SHA-verified against M05. A 3D view from source-referenced heights is still provisional. Do not use generated IFC/STEP/DXF to produce quantities, fabrication, structural checks or construction instructions. M07 does not ingest or republish original Narayani drawings; actual site-specific vertical facts are not introduced into the public source.

The five-engine integration milestone is still **limited to column geometry**. A production CAD authoring engine additionally needs floors, walls, openings, join conditions, relationships, clash checks, signed evidence, 2-way IFC round-trip editing, persistent authenticated project storage, and project-level approvals. Do not call this a completed Revit-equivalent.

Regression evidence: `backend/tests/test_vertical_interchange.py` validates real round-trips (native DXF read, IFC4 profile types and lengths, OpenCascade STEP solids), negative SHA/height/evidence cases, manifests and overwrite safety. `tools/site/cad-m07-browser.mjs` checks WebIFC/Three.js reading IFC generated by the local native bridge on phone and desktop.
