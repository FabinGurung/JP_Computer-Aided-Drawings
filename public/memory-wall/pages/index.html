Narayani's frozen V02–M80 modules, Harisharan's provisional plinth ledger, Ashok's coordination and Ramachandra's missing public source remain distinct. The same 16-slot QA shell does not make them equally approved.

1.2 · Four directions and hierarchy

CAD-PAGES-MEM-01-02-01

1.2.1 · Cardinal navigation contract

NORTH: project and chapter tabs. WEST: version and 3-level chapter tree. EAST: source and package inspector. SOUTH: package dock. CENTER: actual plan/model and content.

CAD-PAGES-MEM-01-02-02

1.2.2 · Responsive accessibility

Desktop split plan left/model right; on mobile, views stack, west rail is labelled, east inspector follows content, south dock scrolls horizontally. Restore deep links, keyboard focus and legible controls.

2 · Authority, sources and history

2.1 · Source ownership

CAD-PAGES-MEM-02-01-01

2.1.1 · Drive owns originals; GitHub owns code

Original PDF/DWG/DXF, native current Docs/Sheets, field evidence and privacy live with their governed providers. This CAD repo owns public-safe UI, geometry version references, schemas, guides and tests; A7 is read-only.

CAD-PAGES-MEM-02-01-02

2.1.2 · Do not simulate technical approvals

Pages, Vercel preview, a saved JSON snapshot or a frozen V02 viewer cannot create engineer acceptance, site instructions, owner sign-off, live Sheets sync or an IFC construction release.

2.2 · Versioning

CAD-PAGES-MEM-02-02-01

2.2.1 · Never overwrite historical sources

Keep actual Git commits, frozen Narayani stage trees, source fingerprints, canonical design editions, old record.html interfaces and exact original URLs. Changes in shared UI do not create a new house design edition.

CAD-PAGES-MEM-02-02-02

2.2.2 · One live Doc ID; numbered archives

For maintained native Docs/Sheets: resolve source, archive and read back prior content, revision-guard update the same current ID, append PRE/POST receipts. Native Drive writes are distinct from Actions; never publish private provider IDs.

3 · Privacy and trustworthy display

3.1 · Public projection

CAD-PAGES-MEM-03-01-01

3.1.1 · Allowlist fields for Pages

Only publish data selected as safe for public display, respecting permissions. Do not dump original confidential financial, personnel, client, restricted provider URLs or private site photos into public assets.

CAD-PAGES-MEM-03-01-02

3.1.2 · Unknown values stay unknown

Use null, NOT ADMITTED, REVIEW REQUIRED and engineering HOLD. Missing rebar schedule, soil report, approved mix or source measurement must not become 0, approved, copied from a peer project or a guessed default.

3.2 · Site workbenches

CAD-PAGES-MEM-03-02-01

3.2.1 · Source viewer vs normalized QA slots

A package record links to an original module. A normalized slot is a gate and checklist; it may remain empty, and an existing linked study may cover multiple slots without becoming multiple independent signed BBS packages.

CAD-PAGES-MEM-03-02-02

3.2.2 · Never invent browser controls

Do not show active PDF export, publish/freeze, submit-to-site or Google Docs editing buttons without implemented authenticated workflows. Quick links can only open verified original routes or copy real share URLs.

4 · Actions and testing

4.1 · Build gates

CAD-PAGES-MEM-04-01-01

4.1.1 · PR stage controls

Use a bounded CAD branch and PR. Validate source preservation, JSON schema, project IDs, honest acceptance statuses, null unknown quantities, four-direction UI, 16 readiness slots and the fictional dummy boundary.

CAD-PAGES-MEM-04-01-02

4.1.2 · Shared geometry safety

Run the existing project-workspace, Harisharan takeoff, Ashok coordination, Narayani source and frozen stage hash tests. Do not bypass a failing test by suppressing it or by changing a frozen source.

4.2 · Browser gates

CAD-PAGES-MEM-04-02-01

4.2.1 · Real mobile and desktop checks

Test the four real project pages, the empty dummy, each project Memory Palace and the Publishing Memory Palace. Verify 3-level TOCs, original links, search/filter, keyboard controls, overflow, and synchronized 2D/3D without inventing remote auth.

CAD-PAGES-MEM-04-02-02

4.2.2 · Block on failures

A green UI smoke test is not engineering certification. Fail CI on untrusted IDs, synthetic data in real registries, unknown-to-zero coercion, missing source manifests or revoked links.

5 · Publication and rollback

5.1 · Verified release flow

CAD-PAGES-MEM-05-01-01

5.1.1 · Merge only tested head

Require required PR checks on the exact head SHA. Re-read main, merge only on matching expected SHA, then wait for successful main-branch staging and the production Pages workflow.

CAD-PAGES-MEM-05-01-02

5.1.2 · Readback live—not just build

GitHub Pages publication success is not the same as live readback success. Verify public HTML/JS bundle, project routes, original stage files and key browser behavior against the deployed merge SHA before claiming end-to-end complete.

5.2 · Recovery and audit

CAD-PAGES-MEM-05-02-01

5.2.1 · Preserve known-good commits

Use Git history for rollback, not deletion of old source designs or replacing old stage directories. Check Pages provenance and hosted asset cache; make corrections through a new bounded PR.

CAD-PAGES-MEM-05-02-02

5.2.2 · Separate status words

Report PREPARED (file only), PR OPEN, CI GREEN, MERGED, DEPLOYED and LIVE READBACK VERIFIED separately. No fake success before the provider reports it.

6 · New-project and poster maintenance

6.1 · Empty dummy onboarding

CAD-PAGES-MEM-06-01-01

6.1.1 · The dummy is a guardrail—not a site

Use /projects/example-empty/ with the exact five-chapter workspace, 16 empty package slots and project Memory Palace. It is synthetic and excluded from real project counts; no steel sizes, prices, soil, dates or geometry exist.

CAD-PAGES-MEM-06-01-02

6.1.2 · Admit real data deliberately

Register a new ID and read actual source drawings; determine jurisdiction/occupancy; validate source fidelity; populate package evidence and calculations from accepted inputs; independently QA; deploy only authorized safe projections.

6.2 · Poster lifecycle

CAD-PAGES-MEM-06-02-01

6.2.1 · Three-level TOC required

Every memory-wall page has chapter n, section n.m, subsection n.m.k with visible headings and working anchor navigation. Posters use stable logical IDs with source, review, revision and acceptance semantics.

CAD-PAGES-MEM-06-02-02

6.2.2 · Never turn a lesson into a requirement blindly

Site anecdotes, rod estimation formulas and prior project assumptions remain reference posters until source-specific design and code review. Update posters through CAD PR/CI; keep the prior Git revision available.
