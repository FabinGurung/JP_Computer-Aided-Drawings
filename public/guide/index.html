AI-Aided Drawing.
Describe it. Explore it.

You explain what building or detail you want in ordinary language. ChatGPT (or another AI) helps interpret your words and existing drawings. Our versioned GitHub CAD engine checks the facts and computes the geometry. The website shows a clickable 3D-first result, with 2D views and deeper detail only where the sources support them.

What happens after you describe a drawing?

Human request→AI interpretation→Versioned validation→CAD engine→3D / drawings
01 · UNDERSTAND

Tell us what you need

Use words, dimensions or an existing drawing. You do not write a prompt schema or technical parameter file.

02 · RESOLVE

Interpret and find sources

AI checks what you said against existing drawings, revisions and authority. It asks only for missing facts.

03 · VALIDATE

Validate real measurements

GitHub-versioned validators verify quoted dimensions, units, IDs, source revisions and unapproved assumptions.

04 · EXECUTE

Run the CAD engines

Three.js, web-ifc, IfcOpenShell, OpenCascade and ezdxf each contribute their existing tested capabilities.

05 · VERIFY

Check geometry and evidence

Regression tests and provenance checks protect reproducibility; licensed design sign-off is separate.

06 · VIEW

3D first, more when clicked

Choose levels and elements, filter trades and inspect source-linked plans, sections, labels and details.

07 · TRACE

Replay the approved inputs

Keep the exact source, canonical request, engine commit, runtime version, QA and output manifest.

ChatGPT guides and interprets; GitHub executes versioned software through its CI or an authorized runner. GitHub does not automatically acquire the hidden capabilities of any AI model. Different AI systems can use the same public contract and deterministic engines, but identical casual sentences do not guarantee identical interpretations.

One building, progressive detail

You should not need to navigate ten technical subpages to understand what happens at site. Open the building, then drill into the area and task you need.

3D · Main view

Orbit the building, select a floor and show/hide systems. Existing browser preview currently supports simple geometric envelopes and other synthetic CAD capabilities.

2D · Precise views

Plans, elevations, sections, details, dimensions and labels derived from the validated model. Specific detailed drawing families require verified source geometry.

4D · Build sequence

Link components to governed scheduling tasks, milestones, predecessors and work progress. This is a planned integration, not automatically live.

5D · Cost / quantity

Link source-supported quantities to the separate cost repository and approved rates. Not a currently approved quantity takeoff.

Workers · Where do I click to know what work is needed?

Planned flow: open project → select floor/room/work package → select element → see simple colored work diagram, dimension callouts, required material and step labels. Show “ISSUED FOR CONSTRUCTION” only when the actual owning engineering authority has approved that exact revision. Until then, mark the item DRAFT / HOLD.

Engineers · How are details, checks and sources shown?

Inspect exact source revision, element ID, constraints, local coordinates, technical dimensions, sections, native IFC/DXF/STEP geometry, verification results, and conflicting/unresolved assumptions. Do not infer rebar, material grades, wall thickness or connection capacity without evidence.

Owners · How will milestones, budgets and progress be connected?

CAD supplies model component IDs; Scheduling owns tasks/dates; Cost owns the rate and BOQ logic; Operations owns evidence of performed field work. A7 links these as peer modules; it does not copy their authorities into one website.

What is genuinely available now?

Current truth: M12.1 provides an English dimension-to-3D volume preview and separate synthetic native CAD generators. The actual Narayani current sources are restricted DWG revisions, not verified DXF conversions. Real-project BIM generation, complete worker-detail sheets, schedule/cost linkage, and engineering acceptance are not yet implemented or approved.

When facts are missing, the system should request only those inputs. Never silently invent beam sizes, column locations, reinforcement, construction stages, prices or material grades. Public demo data is not a site instruction.

Codes and stable document versions

CAD Memory Wall explains one current Google Doc per logical ID, archive-before-update revisions and source responsibilities. The Nepal / Pokhara Code Library holds clause-linked constants, complete official source links and ten local residential references. The shared template is now v0.3.0 at its existing canonical path.

For developers and AI agents

This website follows the CAD-owned AAD template. A7 is the read-only catalogue of ownership, links, history and navigation; A7 does not own or execute this drawing template. The implementation is preserved in GitHub commits and checked with CI.

View the machine contract and reproduction rules

Reproducibility needs identical normalized input, source hashes/versions, pinned engine commit, deterministic runtime settings and verified output hashes. The AI-to-engine interface is conversation_contract.py; DXF inventory is dxf_inventory.py. Exact source code, test and export boundaries live in the owning repository.
